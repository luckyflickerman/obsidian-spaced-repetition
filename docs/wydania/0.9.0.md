# Wydanie 0.9.0 — podsumowanie dla przyszłych sesji

Pierwsza publiczna beta forka jako **Upgraded Spaced Repetition**. Wydana 2026-10-05 (GitHub Actions „Release” zakończony sukcesem, wydanie `0.9.0` z plikami `main.js`, `manifest.json`, `styles.css` i zipem). Użytkowniczka instaluje plugin przez **BRAT** na Windows, iPadzie i iPhonie.

Ten plik opisuje stan po 0.9.0, decyzje i pułapki. Zasady ogólne są w `CLAUDE.md`. Zmiany widoczne dla użytkownika są w `CHANGELOG-UPGRADED.md`.

## Co weszło w 0.9.0

1. **Tożsamość:** `manifest.json` (bez `fundingUrl`, `helpUrl` → README), `package.json`, `versions.json`.
2. **Brak kolizji z oryginałem** (oba pluginy mogą być włączone naraz, sprawdzone bez błędów w konsoli):
    - widoki: `usr-spaced-repetition-tab-view` (`SR_TAB_VIEW`), `usr-review-queue-list-view` (`REVIEW_QUEUE_VIEW_TYPE`),
    - ikona: `usr-spaced-repetition-icon` (`APP_ICON` w `src/icons/app-icon.ts`) — używaj stałej, nie napisu,
    - komendy są automatycznie prefiksowane id pluginu; nowe komendy forka mają id z prefiksem `usr-`.
3. **Sprawdzanie aktualizacji** (`status-bar-manager.tsx`) pyta `api.github.com/repos/<PLUGIN_REPO>/releases/latest` i porównuje `tag_name` z `manifest.version` (równość, nie „nowsza”). Dlatego zwykłe wydania nie mogą być oznaczone jako pre-release.
4. **Linki w ustawieniach** (`main-page.tsx`): zgłoszenia, pytania i kod → repozytorium forka. Dokumentacja, roadmapa i newsy → oryginał (celowo).
5. **Import z oryginału** — moduł `src/migration/`:
    - `legacy-import.ts` (czysta logika, testy w `tests/unit/migration/`): `parseLegacyData` (uszkodzony JSON → `ok:false`), `buildImportedData` (najpierw `upgradeSettings` na starych ustawieniach, **potem** domyślne + wszystkie `normalize…`; odwrotna kolejność psuje konwersję starych opcji), `shouldOfferImport`.
    - `legacy-import-controller.ts`: okno Tak / Nie / Później (zamknięcie = Później) i komenda `usr-import-original-data`. Plik oryginału czytany przez `app.vault.adapter` (działa na telefonie), **nigdy zapisywany**. Po imporcie: `saveData`, komunikat z prośbą o wyłączenie oryginału, przeładowanie pluginu przez prywatne `app.plugins.disablePlugin/enablePlugin` (gdy brak — komunikat o restarcie).
    - Stan w `data.json`: `legacyImport` = `pending` (Później → pytaj przy każdym starcie) / `declined` / `done`. Okno pojawia się tylko, gdy plugin nie miał własnych danych przy starcie (`PluginDataManager.loadedEmpty`) albo stan to `pending`, i tylko gdy plik oryginału istnieje.
    - Przenoszone jest wszystko z `data.json` oryginału, łącznie ze `scheduleData` (jedyny magazyn to notatki, więc harmonogram i tak jest w `<!--SR:…-->`). **Nie** przenoszą się skróty klawiszowe z `.obsidian/hotkeys.json` (są przypisane do id komend).
6. **Automatyczne wydania** (`.github/workflows/release.yml`): patrz niżej.
7. **CI testów** (`test.yml`): bez Codecov. Lint na Linuksie przechodzi (sprawdzaj lokalnie `npx prettier --check --end-of-line auto .`).
8. **Dependabot:** raz w miesiącu, zbiorczy PR, bez pip i bez wersji major.
9. **Dokumentacja:** nowy `README.md` (EN + sekcja PL, zrzuty w `docs/screenshots/`), stary README → `docs/README-original.md`, `CHANGELOG-UPGRADED.md`, `LICENSE` z dopisanym `Copyright (c) 2026 luckyflickerman`, `SPEED-STREAK-README.md` (instalacja przez BRAT).

## Jak wydać nową wersję

1. Zmień wersję w **trzech** miejscach: `manifest.json`, `package.json`, `versions.json` (`"x.y.z": "<minAppVersion>"`).
2. Dopisz sekcję `## x.y.z` na górze `CHANGELOG-UPGRADED.md`. Workflow bierze z niej opis wydania (nagłówek musi być dokładnie numerem wersji).
3. `npx tsc -noEmit -skipLibCheck`, `node esbuild.config.mjs production`, `npx jest`, `npx prettier --check --end-of-line auto .`.
4. Scal do `main`. Użytkowniczka robi **push** w GitHub Desktop, potem **History → prawy przycisk na commicie → Create Tag** → `x.y.z` (**bez `v`**) → **Push origin**.
5. Workflow przerywa, gdy tag ≠ `version` w `manifest.json`. Tag z myślnikiem (`1.0.0-beta.1`) = pre-release. Zwykły tag = „latest” (wymagane przez sprawdzanie aktualizacji).
6. BRAT na urządzeniach (z „Auto-update plugins at startup”) instaluje nowe wydanie przy starcie Obsidiana. Zmiany bez taga nie trafiają do użytkowniczki.

## Środowisko na komputerze użytkowniczki (Windows) — pułapki

- **Brak `pnpm` i `git` w PATH.** `pnpm build` nie zadziała (skrypt woła `pnpm install`). Zamiast tego: `npx tsc -noEmit -skipLibCheck` i `node esbuild.config.mjs production`, testy: `npx jest`. Git jest w GitHub Desktop:
  `$env:Path="C:\Users\jerzy\AppData\Local\GitHubDesktop\app-3.6.6\resources\app\git\cmd;$env:Path"` (numer wersji w ścieżce może się zmienić). `awk` jest w `...\git\usr\bin\awk.exe`, bash nie.
- **PowerShell 5.1 i polskie znaki.** Wiadomości commitów zapisuj narzędziem Write do pliku UTF-8 i używaj `git commit -F plik`. Here-stringi w `.ps1` bez BOM są czytane jako ANSI i psują znaki („ĹšcieĹĽki”). Przekazanie wiadomości przez stdin (`-F -`) nie działa.
- **Końce linii:** git ma `autocrlf`. Po buildzie `styles.css` często jest „zmieniony” tylko przez CRLF — sprawdź `git diff --ignore-cr-at-eol` i przywróć `git checkout -- styles.css`, jeśli treść jest ta sama.
- **Obsidian i CDP:** uruchamiany z `--remote-debugging-port=9222`. Brak Playwrighta w projekcie — wystarcza surowy CDP przez wbudowany `WebSocket` w Node 24 (`/json/list`, `Runtime.evaluate`, `Page.captureScreenshot`, `Emulation.setDeviceMetricsOverride` dla 390×844). `app.emulateMobile()` **przeładowuje** aplikację — przełącz, poczekaj na `app.workspace.layoutReady`, dopiero potem działaj. Okno powtórek ma własny X (nie `.modal-close-button`) — zamykaj klawiszem Escape (`Input.dispatchKeyEvent`).
- **Prawdziwy vault:** jeśli Obsidian działa bez portu debugowania, może mieć otwarty prawdziwy vault użytkowniczki („cała wiedza”). **Nie zamykaj go sam** — poproś ją.
- **dev-vault:** `node scripts/dev-vault-install.mjs` (folder i id z `manifest.json`), `--bez-danych` = bez startowego `data.json` (test importu). W `dev-vault/.obsidian/plugins/obsidian-spaced-repetition/` leży stara kompilacja forka — pełni rolę „oryginału” w testach importu i ma przykładowe dane (tag `#IMPORT-TEST`, rekord Speed Streak 42).
- **Brak `actionlint`.** Workflow sprawdzany przez parsowanie `js-yaml` z `node_modules/.pnpm/node_modules/js-yaml` i test logiki `awk` na `CHANGELOG-UPGRADED.md`.

## Znane ograniczenia i otwarte sprawy

- **Klasy CSS** (`sr-*`, `#sr-modal-view`) są wspólne z oryginałem. Gdy oba pluginy są włączone, style jednego mogą wpływać na drugi. Oba pluginy razem to stan przejściowy — użytkowniczka ma wyłączyć oryginał.
- **Rozmiar `main.js` 3,4 MB** w 0.9.0 (mapa źródeł inline + brak minifikacji). Poprawka w gałęzi `wydanie-0.9.1`: bez sourcemap w produkcji, minifikacja **tylko JS** (`esbuild.transform`, `keepNames`) → ok. 1,2 MB. **CSS nie minifikować:** esbuild zamienia `& > .x` na `> .x` (nie działa w Safari iOS < 17.2) i usuwał regułę `.is-mobile … .sr-extended-menu-button`. Przed wydaniem 0.9.1 trzeba ją sprawdzić w prawdziwym Obsidianie.
- `SPEED-STREAK-README.md`, sekcja „Pominięte z oryginału”, wymienia Fusion Rings i Crystal Reactor jako pominięte, a są zaimplementowane jako style 2D — do poprawy.
- Zrzut `docs/screenshots/import.png` ma w rogu powiadomienie BRAT z dev-vault — kosmetyka.
